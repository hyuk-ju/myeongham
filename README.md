# 명함첩

받은 명함을 찍어두면 필요할 때 찾아주는 개인용 명함 관리 앱.

목적은 저장이 아니라 **질의**입니다:

> "A라는 설비를 만들 수 있는 회사와 담당자 전화번호·메일주소 정리해줘"

이 한 문장에 필요한 연락처가 표로 나오는 것이 이 앱의 목표입니다.

---

## 무엇을 하나

| 화면 | 하는 일 |
|---|---|
| 홈 | 등록 수, 역량 태그 없는 명함 수, 최근 등록, 검색 |
| 담기 | 사진을 여러 장 한 번에 담고, 분석·회사 조사는 뒤에서 순차 진행 |
| 확인 | 분석 끝난 명함을 한 장씩 확인·수정 → 저장 |
| 태그 채우기 | 역량 태그가 빈 명함을 회사 단위로 모아서 보강 |
| 명함 | 목록·검색·태그 필터, 상세 수정/삭제, 같은 회사 동료, 명함 이력 |
| 질문 | 자연어로 물으면 조건 검색 후 AI가 연락처 표로 정리 (복사·CSV) |
| 설정 | AI 연결(ChatGPT/Claude), 작업별 모델 선택, 계정 |

### 핵심 설계 — 촬영·분석·검토 분리

명함 한 장당 AI 인식이 10~30초 걸립니다. 예전에는 그 시간을 화면 앞에서 기다린 뒤에야
다음 장을 찍을 수 있어서, 20장이면 분석 대기만 5~10분이었습니다.

지금은 셋을 떼어놨습니다.

1. **담기** — 사진만 올리고 곧바로 다음 장 (앨범은 여러 장 한 번에)
2. **분석** — 뒤에서 한 장씩 순차 처리. 찍는 시간과 겹쳐서 흘러갑니다
3. **확인** — 다 담은 뒤 몰아서 확인·저장

대기열은 `card_drafts` 테이블에 남습니다. 앱을 껐다 켜도 남은 것부터 이어서 하고,
폰에서 담고 PC에서 확인해도 됩니다.

> `cards` 에 `status='extracted'` 로 담지 않고 **테이블을 나눈** 이유: 목록·검색·질문·
> 중복검사 등 읽기 경로 13곳에 필터를 넣어야 하고, 한 곳만 빠뜨리면 **검토 안 한 OCR
> 결과가 질문 답변에 섞입니다.** 테이블이 다르면 그런 실수가 구조적으로 불가능합니다.

분석 동시성은 **1** 입니다. 구독 OAuth 에는 429 재시도 계층이 없어서 동시에 부르면
한도만 빨리 태웁니다. 한도에 걸리면 큐를 멈추고 *다시 시도* 를 띄웁니다.

### 핵심 설계 — 역량 태그

명함에는 "이 회사가 무엇을 만드는지"가 거의 안 적혀 있습니다. OCR 만으로는 위 질의에
답할 수 없어서, `capabilities` 태그를 네 경로로 채웁니다.

1. 명함 텍스트에서 추출 (자동)
2. **같은 회사 명함에서 재사용** — *같은 회사 명함에서 가져오기*
3. **회사명 웹 검색으로 보강** — 대기열에서 **회사 단위로 자동** 조사해 두고,
   확인 화면에서 고르기만 하면 됩니다. 놓친 것은 홈의 *역량 태그 채우기* 에서 일괄 처리
4. 사용자가 직접 입력 (가장 정확)

3번은 오답 가능성이 있어 **자동 저장하지 않고** 제안만 하며, 사용자가 고른 것만
담깁니다 (`capabilities_source` 에 근거를 기록).

2번이 3번보다 위에 있는 이유: 태그는 사람이 아니라 **회사**에 붙는 정보입니다.
같은 회사 사람을 세 명 등록할 때 웹 검색을 세 번 돌리면 20~40초를 세 번 쓰고도
태그가 카드마다 달라집니다. 그러면 *"이 회사 뭐 만들어?"* 질문에 한 사람만 걸리고
동료가 빠집니다. 회사명 표기 흔들림((주)선진템 / 주식회사 선진템)은
`normalize_company()` 가 흡수합니다.

## 기술 구성

- **Next.js 16** (App Router) / TypeScript / Tailwind CSS 4 / PWA
- **Clerk** — 로그인 (Google 등 소셜). `ALLOWED_EMAILS` 로 이중 차단
- **Supabase** — Postgres + Storage. RLS 는 Clerk 세션 토큰의 `sub` 기준
- **AI** — ChatGPT(Codex) 또는 Claude **구독 OAuth**. API 키를 쓰지 않아
  토큰당 과금이 없습니다. **명함 인식 / 질문 답변 / 회사 정보 검색** 세 작업에
  각각 다른 AI·모델을 지정할 수 있어, 한쪽이 한도에 걸리면 반대쪽으로 넘길 수 있습니다.
  웹 검색은 양쪽 다 지원합니다 (Claude `web_search_20250305`, Codex `web_search`).

AI 호출은 `lib/ai/llm.ts` 한 곳으로 모입니다. 비공식 표면(Codex 백엔드)은
`lib/ai/codex.ts` 에 격리돼 있어 바뀌어도 한 파일만 고치면 됩니다.

## 알아둘 것

- **OCR 은 100% 가 아닙니다.** 확인·수정 단계를 생략하지 않습니다. 잘못 저장된
  연락처는 나중에 질의 결과를 조용히 오염시킵니다.
- **개인정보**: 명함은 성명·연락처·소속이 결합된 개인정보입니다. 외부 클라우드
  (Supabase/Clerk/AI 제공자)에 저장·전송하는 구성이 사내 규정상 허용되는지
  확인해 두시길 권합니다.
- 전화번호는 국가번호(+82/+84)를 현지 표기로 자동 변환해 저장합니다.
